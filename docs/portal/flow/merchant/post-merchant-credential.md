this api use for create the credential (`client_id` and `client_secret`) of a merchant for a provider (used in merchant detail page). Only Product Owner can create a credential. The `client_id` and `client_secret` are generated by the system. The `client_secret` is returned only once in this response, only its hash is stored, it can never be read again (use [rotate credential](post-merchant-credential-rotate.md) to get a new one).

**Method**: POST

**Path**: /api/v1/merchants/:id/credentials

**Permission**: `merchant_credentials:create`

request headers:

| key           | value              | required | description                                                          |
| ------------- | ------------------ | -------- | -------------------------------------------------------------------- |
| Authorization | `Bearer <token>`   | true     | access token from [login](../auth/post-login.md) (or cookie `token`) |
| Content-Type  | `application/json` | true     | request body format                                                  |

request path:

| param | type   | required | description  |
| ----- | ------ | -------- | ------------ |
| id    | string | true     | merchant uid |

request query:

none

request body:

| key      | type   | required | description                                    |
| -------- | ------ | -------- | ---------------------------------------------- |
| provider | string | false    | `POS_CASHIER`, default `POS_CASHIER`           |

example request body:

```json
{
  "provider": "POS_CASHIER"
}
```

response body (fields below are the value of `data`, wrapped in [Ok](../../../apiresponse/middleware.md#ok)):

| key           | type   | description                                                   |
| ------------- | ------ | ------------------------------------------------------------- |
| merchant_uid  | string | merchant uid                                                  |
| provider      | string | `POS_CASHIER`                                                 |
| client_id     | string | client id (generated, unique)                                 |
| client_secret | string | client secret (generated, **shown only in this response**)    |
| created_at    | string | created date time (ISO 8601)                                  |

example response body:

```json
{
  "res_code": "0000",
  "res_desc": "",
  "data": {
    "merchant_uid": "string",
    "provider": "POS_CASHIER",
    "client_id": "string",
    "client_secret": "string",
    "created_at": "2026-10-22T10:00:00.000Z"
  }
}
```

Logic:

- Verify access token
  - if fail throw [ServiceError.ErrTokenInvalide](../../../apiresponse/ServiceError.ts)
- Check access token expire
  - throw [ServiceError.ErrTokenExpire](../../../apiresponse/ServiceError.ts)
- Validate Permission `merchant_credentials:create` follow [uam](../../uam.md)
  - throw [ServiceError.ErrPermissionDenied](../../../apiresponse/ServiceError.ts)
- DTO Request
- Validate request path with zod schema
  - id
    - type: string
    - min: 1
    - required: true
- Validate request body with zod schema
  - provider
    - type: enum `POS_CASHIER`
    - required: false
    - default: `POS_CASHIER`
  - If validation fails, throw [ValidationError.ErrInvalidRequest](../../../apiresponse/ValidationError.ts)
- Find merchant by uid (path `id`)
  - if not found, throw [ServiceError.ErrMerchantNotFound](../../../apiresponse/ServiceError.ts)
- Check the merchant has no credential of this `provider` yet
  - if exists, throw [ServiceError.ErrMerchantCredentialExists](../../../apiresponse/ServiceError.ts)
- Generate `client_id`
  - `cid_` + 16 random bytes (CSPRNG) as hex
  - if `client_id` already exists, generate a new one and retry
- Generate `client_secret`
  - `cs_` + 32 random bytes (CSPRNG, `crypto.randomBytes`) as base64url
- Hash `client_secret` with SHA-256 (hex), the secret is random and high entropy so a slow hash is not required. Never store or log the plain secret
- Create `merchant_credential` in database (merchant_id, provider, client_id, client_secret = hash)
  - if the unique `(merchant_id, provider)` is violated (concurrent request), throw [ServiceError.ErrMerchantCredentialExists](../../../apiresponse/ServiceError.ts)
- DTO Response
- wrap the response with [Ok](../../../apiresponse/Ok.ts) (`res_code` `0000`), the response items below are `data`
- response `201 Created` with credential follow these items (merchant_uid, provider, client_id, client_secret (plain, only here), created_at)
- do not write `client_secret` into any log, including the request logger
